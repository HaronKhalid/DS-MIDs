Introduction to Data Science

Definition, history, applications, how it differs from AI, ML and analytics, the lifecycle and the roles in a data team.

What is Data Science?

Data Science means getting useful insights from raw data. It mixes statistics, programming and domain knowledge.
  • Statistics: understand patterns and uncertainty.
  • Programming: collect, clean and analyse data at scale (Python, R, SQL).
  • Domain knowledge: know what the numbers mean for the real problem.

Exam definition: Data science is an interdisciplinary field that combines mathematics, statistics, computer science, artificial intelligence and domain expertise to extract meaningful insights and knowledge from raw, structured or unstructured data.

Data Cleaning

Missing values, duplicates, inconsistent data, outliers, encoding and scaling. Raw data is almost never ready to use.

What is data cleaning? The workflow

Data cleaning = detecting and correcting inaccurate, incomplete, inconsistent, duplicate or irrelevant data. Notes: fix weak or missing data; incorrect and duplicate values.
  1. Inspect the data (shape, info, describe, null check).
  2. Remove duplicates.
  3. Handle missing values.
  4. Fix types and inconsistent values (spelling, case, units).
  5. Investigate outliers.
  6. Encode categories and scale numbers if the model needs it.
  7. Check again.
Exam focus: cleaning is not simply deleting bad rows. First understand why a value is missing, wrong or unusual.

import pandas as pd

Duplicates and inconsistent data

  • Duplicates: the same record twice. df.drop_duplicates() keeps the first copy.
  • Inconsistent values: “Lahore”, “lahore ” and “LAHORE” are the same city written differently. Standardise spaces, case, units and spelling.
import pandas as pd
df = pd.DataFrame({"city": ["Lahore", "lahore ", "Karachi", "Lahore"]})
df["city"] = df["city"].str.strip().str.title()
print(df["city"].tolist())
print(len(df.drop_duplicates()))

After cleaning the text, only two distinct rows remain (Lahore, Karachi). Clean the text before looking for duplicates.

Outliers

An outlier is a value far from the others. Detect it, then investigate: is it an error (fix it) or a real rare value (keep it)?

IQR rule: outlier if the value is below Q1 − 1.5×IQR or above Q3 + 1.5×IQR, where IQR = Q3 − Q1. Another idea: a very large |z-score| (for example above 3).

import pandas as pd
s = pd.Series([30, 32, 35, 36, 38, 40, 45, 160])
q1, q3 = s.quantile(0.25), s.quantile(0.75)
iqr = q3 - q1
print(q1, q3, s[(s < q1 - 1.5*iqr) | (s > q3 + 1.5*iqr)].tolist())

Q1 = 34.25, Q3 = 41.25, IQR = 7, upper fence = 51.75, so 160 is an outlier.

Feature scaling: normalisation and standardisation

Min-max normalisation: (x − min) / (max − min) → values from 0 to 1.
Standardisation (z-score): (x − mean) / SD → mean 0, SD 1.

Worked example with 20, 30, 40, 50, 100 (min 20, max 100, mean 48, SD ≈ 27.86): the age 40 scales to (40 − 20) / 80 = 0.25; the age 100 has z = (100 − 48) / 27.86 = 1.87.

x = [20, 30, 40, 50, 100]
lo, hi = min(x), max(x)
print([round((v - lo) / (hi - lo), 3) for v in x])
mean = sum(x) / len(x)
sd = (sum((v - mean) ** 2 for v in x) / len(x)) ** 0.5
print(round(mean, 1), round(sd, 2), round((100 - mean) / sd, 2))
Data leakage: learn the min, max, mean and SD (and imputation values) from the training data only, then apply them to the test data.

Filtering and sorting

Filtering keeps rows where a condition is True: df[df["marks"] > 60]. Sorting orders rows: df.sort_values("marks", ascending=False).
import pandas as pd
df = pd.DataFrame({"name": ["Ali", "Sara", "Usman"], "marks": [78, 91, 55]})
print(df[df["marks"] > 60]["name"].tolist())
print(df.sort_values("marks", ascending=False)["name"].tolist())

Only Ali (78) and Sara (91) pass the filter; sorted high to low gives Sara, Ali, Usman.

GroupBy and aggregation

groupby = split the rows into groups, apply a function to each group, combine the results.
  • Common aggregations: sum, mean, count, min, max.
  • Group keys come out sorted by default.
import pandas as pd
df = pd.DataFrame({"city": ["Lahore", "Karachi", "Lahore"], "marks": [78, 91, 72]})
print(df.groupby("city")["marks"].mean().to_dict())

Lahore: (78 + 72) / 2 = 75.0. Karachi: 91.0.

Merge and join

merge combines two tables through shared key columns. join combines tables aligning on the index by default. Both support several join types.
Join typeKeeps
inner (default for merge)only rows whose key is in both tables
leftall rows of the left table, matched rows of the right
rightall rows of the right table, matched rows of the left
outerall rows from both tables
import pandas as pd
a = pd.DataFrame({"city": ["Lahore", "Karachi"], "marks": [75, 91]})
b = pd.DataFrame({"city": ["Lahore", "Karachi"], "province": ["Punjab", "Sindh"]})
print(a.merge(b, on="city")["province"].tolist())

Data manipulation overview

Manipulation = transforming and organising data so it can be analysed. Cleaning fixes quality problems; manipulation reshapes data for analysis.
  • Filtering rows, selecting or removing columns
  • Sorting values
  • Grouping and aggregation (sum, mean, count)
  • Merging / joining datasets
  • Creating calculated (derived) columns, changing data types

Order in a project (notes): acquisition (get data) → cleaning (fix quality) → manipulation (Pandas) → visualisation (charts and graphs).

Spread, quartiles and outliers

  1. Mean of 2, 4, 4, 4, 5, 5, 7, 9 = 40 / 8 = 5
  2. Squared deviations: 9, 1, 1, 1, 0, 0, 4, 16 → sum = 32
  3. Variance = 32 / 8 = 4
  4. Standard deviation = √4 = 2
  5. Range = 9 − 2 = 7
The mean is sensitive to extreme values; the median is robust. Quartiles split sorted data into four parts (Q1, median, Q3); IQR = Q3 − Q1. A box plot shows these and the outliers.
Population variance divides by n (as in the lecture definition). When your data is only a sample, software often divides by n − 1.

Correlation and causation

Correlation r = Cov(X, Y) / (sx · sy). It runs from −1 (perfect negative) through 0 (none) to +1 (perfect positive). It shows association, not cause.

Machine Learning Fundamentals

What is Machine Learning? The ML lifecycle

Machine Learning = algorithms that learn patterns from data to make predictions or decisions, instead of following rules written by hand.
  1. Collect data
  2. Prepare it (clean, encode, scale)
  3. Split into training, validation and test sets
  4. Train the model on the training set
  5. Evaluate / validate and tune
  6. Deploy the model
  7. Monitor and retrain when needed

Data leakage: if test rows influence training or tuning (for example scaling on all the data, or tuning on the test set), the score looks better than reality. A common split is about 70–80% training with the rest for validation and testing.

Generalisation and underfitting

A model learns from training data, but its real job is to perform well on new data it has never seen. This is generalisation. Overfitting and underfitting are two ways it fails.
Underfitting: the model is too simple. It has not learned the pattern, so it performs poorly on both training data and new data (high bias).

Causes: too few features, short training, strong regularisation, a model too simple for the pattern.

Overfitting

The model is too complex. It memorises the training data including its noise, so it looks excellent in training but performs poorly on new data (high variance).

Causes: too complex a model, too many features, a small dataset, excessive training.

Good fit, the student analogy and comparison table

Good fit: the model captures the true patterns and performs well on both training data and new data.
  • Underfitting = a student who barely studied.
  • Overfitting = a student who memorised last year's paper word for word.
  • Good fit = a student who understands the concepts and can solve any new question.

Test error is lowest at a medium complexity. Beyond that the model starts to overfit:

ProblemSolutions
UnderfittingUse a model with suitable complexity, add useful features, reduce excessive regularisation, train appropriately.
OverfittingSimpler model, regularisation, cross-validation, feature selection, pruning, early stopping, more representative data.
The numbers in the first table are illustrative, as in your notes. In practice judge by both the level and the gap, not a fixed cut-off.

Rule of thumb: both errors high → add capacity; big gap → reduce complexity or add data.
